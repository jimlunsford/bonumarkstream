# Gate 6A source implementation

## Scope and implementation decisions

This candidate implements site authorization and a separately packaged hosted
relay foundation. Deployment, actual service hostname, infrastructure acceptance,
and a live installation connection remain Gates 6B and 6C. Gate 7 is not started.

The relay lives in repository-only `services/bonumark-connect/`. It uses Node.js
24, JavaScript ES modules, the built-in HTTP/TLS/crypto/test facilities, pinned
mysql2 and ipaddr.js dependencies, and a dedicated MariaDB/MySQL database. This
keeps the asynchronous HTTPS service small while using mature transactional
storage compatible with the existing database/backup operating architecture.
It introduces no Node, database-account, or service dependency into Stream.
No framework, content store, plugin identity assumption, or public signup exists.

Site migration 0030 is reserved solely for the Connect authorization foundation.
Site identity is initialized explicitly by the owner, never by discovery. Trusted
client registration is a deliberate local CLI provisioning action.

## Admin UI reuse

The closest workflow is `admin/remote-posting.php`, owned by
`assets/admin-settings.css`. Connected Applications and approval reuse the shared
Admin header/footer, settings panels, scope controls, responsive record cards,
notices, and separated danger controls. No new visual component is required.
Desktop records become labelled cards on tablet/phone. All controls are native
labelled forms, keyboard-operable without JavaScript. Empty/uninitialized,
unavailable, pending, expired, revoked, error and successful states need distinct
text. Recovery and clone reset require typed confirmation and CSRF-protected POST.
Authorization adds no-store, no-referrer, and a restrictive self-only resource
policy. Local revocation needs no relay call.

## Acceptance limits and next work

No VPS, service deployment, final hostname, DNS, public TLS, systemd, Nginx,
firewall, remote database, backups or roadmap status is changed. Local ephemeral
TLS fixtures are test certificates only. Public v0.8.2 remains the release.

Gate 6A remains a human-review source candidate. Gate 6B must establish least-
privilege deployment, actual host/client registrations, proxy access-log redaction,
operational limits, separate key custody, backup coverage and practical restore.
Gate 6C must verify a real development installation through the accepted hosted
service before Gate 6 closes. Gate 7 remains not started.

A legitimate origin move requires explicit site revocation/reapproval and operator
review of retained relay identity binding. Lost exchange responses and failed
relay disconnects can require local owner revocation. Restored backups must run
the documented recovery revocation before Connect becomes reachable. These limits
are explicit; no automatic rollback, clone detection or trust-transfer guarantee
is claimed.
