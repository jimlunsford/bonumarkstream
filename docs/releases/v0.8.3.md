# Bonumark Stream v0.8.3: Timestamp Correction Hotfix

**Prepared release candidate, not publicly released.** The current public release is [v0.8.2](https://github.com/jimlunsford/bonumarkstream/releases/tag/v0.8.2), published September 26, 2026. Merge, tagging, public release publication, and production deployment require Jim's separate approval.

This focused PATCH candidate packages the accepted RSS and sitemap timestamp correction from PR #23, merged at `64b6049546c5ecd684558346d06441b67a7bc5f2` with source tree `27316ecdab046a24899fd6aa5c0e15d97d2a3038`. Release preparation changes identity, cache version, documentation, and the final manifest. The accepted correction and its regression tests remain unchanged.

## RSS publication times

The previous RSS path could parse a UTC database publication value as site-local time, shifting the represented instant by the local offset. A post shown at 6:45 AM EST could consequently appear in RSS at 11:45 AM EST.

RSS now uses the same public publication-time interpretation as the post. UTC database values represent UTC instants; explicit offsets are respected; authored/imported local fallback dates remain local. Scheduled posts retain the intended scheduled publication instant even when the scheduler runs later. Feed build time remains the feed's build time, and editing a post does not turn its RSS publication date into a modification date.

## Sitemap modification dates

Sitemap `lastmod` continues to prioritize modification time (`updated_at`) for individual content. Database creation and modification values are interpreted as UTC. Publication timestamps retain the existing historical cutover policy, and authored local fallback values retain site-local interpretation. Hydrated copies of scheduled or publication fields use the originating field's timezone. Explicit offsets take precedence.

Collection dates retain their existing maximum-candidate behavior, with each candidate interpreted correctly. A sitemap modification date may legitimately differ from RSS publication time after an edit. The correction does not change sitemap enablement, indexing rules, URL inclusion, or existing missing/invalid-date fallback behavior.

## Historical timestamps and scheduling

The existing `stream_published_at_utc_cutover` setting remains authoritative. Pre-cutover local publication values keep their historical meaning, and later UTC values keep theirs. No timestamps, content, timezone settings, publication schedules, or historical records are rewritten.

Permanent timestamp regressions cover EST and EDT, spring-forward boundaries, both repeated fall-back hours, explicit offsets, local fallbacks, cutover boundaries, scheduled publication, RSS envelopes, and sitemap field precedence and aggregation. Existing publishing, API, and public-semantics regressions remain part of release verification.

## Upgrade impact

**Adds no database migration.** Migration files remain unchanged through `0028_activitypub_remote_actor_lifecycle.php`. A healthy public v0.8.2 installation has no new migration to run. The supported upgrade line still begins at v0.4.0.

Use the existing Admin ZIP or owner-run upgrade workflow after approval and a verified backup. The package keeps the existing validation, newer-version enforcement, software backup, pre-migration rollback, and forward-only migration recovery behavior. Configuration, installed lock, posts, Pages, settings, accounts, media/uploads, custom themes, ActivityPub identity/state, and the migration ledger remain protected owner data.

Release preparation also corrects stale references that called v0.8.2 unreleased or v0.8.1 the latest public release. The original v0.8.2 artifact is unchanged.

See [Upgrading](../UPGRADING.md), [Installation](../INSTALL.md), and [Compatibility](../COMPATIBILITY.md).
